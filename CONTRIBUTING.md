# Contributing to Metakip

## pnpm Version

This project pins **pnpm to `11.3.0`** across all environments: local machines, VMs, and Docker containers. The lockfile must be produced and consumed by the same pnpm version, otherwise `pnpm install --frozen-lockfile` fails in the Docker build.

**The pinning is in `package.json`** via the `packageManager` field — `pnpm@11.3.0`. Corepack reads this field when you run `corepack enable pnpm` to automatically install and use the correct version.

## Setting Up pnpm Locally

If you do not have pnpm 11.3.0 installed:

```bash
# Using corepack (recommended)
corepack enable
corepack use pnpm@11.3.0

# Verify
pnpm --version  # should print 11.3.0
```

If corepack is not available:

```bash
npm install -g pnpm@11.3.0
```

After switching pnpm versions, run `pnpm install` to regenerate the lockfile.

## Why This Matters

`pnpm install --frozen-lockfile` (used in the Docker build) validates that the lockfile was generated by the same pnpm major version. Pinning to 11.3.0 everywhere ensures the lockfile is always compatible.

## What to Do After Pulling New Code

```bash
git pull origin master
pnpm install
pnpm build
```

If you see lockfile warnings or the install fails with a mismatch error, re-sync:

```bash
pnpm install --no-frozen-lockfile
pnpm install
```

Commit the updated lockfile only if it was legitimately changed by dependency updates — not as a routine sync step.
